## Decisoes aprovadas

### Versao alvo do .NET

**Decisao:** usar **.NET 10 LTS**.

**Justificativa:** em 2026-07-01, a politica oficial da Microsoft lista:

- .NET 10 como LTS, com suporte ate 2028-11-14
- .NET 9 como STS, com suporte ate 2026-11-10
- .NET 8 como LTS, tambem com suporte ate 2026-11-10

Como o projeto pretende evoluir por muitos anos, .NET 10 LTS e a melhor escolha tecnica neste momento.

**Observacao:** a ideia inicial era usar ".NET 9 LTS/estavel se disponivel, senao .NET 8 LTS". Como .NET 9 nao e LTS e .NET 10 LTS esta disponivel no ambiente local, a decisao foi ajustada para preservar suporte longo.

### Nome da solution

**Decisao:** `ProjetoEncontros`.

**Justificativa:** o nome oficial do aplicativo ainda nao foi definido, e toda a documentacao usa o termo Projeto Encontros. A solution deve seguir o mesmo nome para manter consistencia.

### Formato do convite na v0.1

**Decisao:** convite por e-mail.

**Justificativa:** convite por e-mail e simples, compreensivel e suficiente para a fundacao do produto.

**Fora do escopo da v0.1:**

- convite por link publico
- QR Code
- descoberta publica de grupos
- codigo compartilhavel sem controle

### Tempo de expiracao do access token

**Decisao:** 15 minutos.

**Justificativa:** access token curto reduz risco em caso de exposicao do token e combina com uso de refresh token.

### Tempo de expiracao do refresh token

**Decisao:** 30 dias.

**Justificativa:** 30 dias oferece equilibrio entre seguranca e conveniencia, evitando login frequente demais no futuro cliente mobile.

### Estrategia de IDs

**Decisao:** usar `Guid`/UUID.

**Justificativa:** GUIDs sao simples de usar no .NET, evitam exposicao de sequencias numericas e funcionam bem para entidades principais do dominio.

### Idioma do codigo e dos contratos proprios

**Decisao:** usar portugues para codigo proprio, nomes internos de projeto e contratos de API definidos pelo Projeto Encontros.

**Justificativa:** o codigo deve preservar a linguagem do dominio e reduzir traducao mental entre produto, documentacao e implementacao.

**Excecoes permitidas:** nomes obrigatorios de framework, bibliotecas, arquivos convencionais e siglas tecnicas estabelecidas, como `Program.cs`, `Guid`, `Task`, `JWT`, `HTTP`, `API` e `DTO`.

### Docker Compose

**Decisao:** criar Docker Compose ja na primeira entrega para PostgreSQL local.

**Justificativa:** isso facilita desenvolvimento, padroniza ambiente e reduz diferencas entre maquinas.

### Swagger/OpenAPI

**Decisao:** usar `Swashbuckle.AspNetCore` na API.

**Versao inicial:** `10.2.3`.

**Justificativa:** Swagger facilita validar contratos durante a construcao backend-only e sera util para o futuro cliente iOS.

### Autenticacao JWT na API

**Decisao:** usar `Microsoft.AspNetCore.Authentication.JwtBearer`.

**Versao inicial:** `10.0.9`.

**Justificativa:** e o pacote oficial do ASP.NET Core para validar tokens JWT em endpoints privados.

### Hash de senha

**Decisao:** usar `BCrypt.Net-Next`.

**Versao inicial:** `4.2.0`.

**Justificativa:** BCrypt e uma escolha segura e estabelecida para armazenar senhas com hash adaptativo, evitando senha em texto puro no banco.

### Geracao de JWT

**Decisao:** usar `System.IdentityModel.Tokens.Jwt`.

**Versao inicial:** `8.14.0`.

**Justificativa:** e uma biblioteca oficial do ecossistema Microsoft para gerar tokens JWT assinados.

### Armazenamento de refresh token

**Decisao:** o refresh token deve ser retornado ao cliente apenas uma vez e armazenado no banco somente como hash SHA-256.

**Justificativa:** se o banco for exposto, o token renovavel nao deve estar disponivel em texto puro.

### Renovacao de sessao

**Decisao:** usar rotacao de refresh token.

Ao renovar uma sessao, o refresh token usado deve ser revogado e um novo refresh token deve ser emitido.

**Justificativa:** isso reduz a janela de risco caso um refresh token seja capturado, pois o token antigo deixa de ser reutilizavel apos uma renovacao bem-sucedida.

## Configuracoes iniciais derivadas

### Backend

- Target framework: `net10.0`
- Solution: `ProjetoEncontros.sln`
- Projetos:
  - `ProjetoEncontros.Api`
  - `ProjetoEncontros.Aplicacao`
  - `ProjetoEncontros.Dominio`
  - `ProjetoEncontros.Infraestrutura`
  - `ProjetoEncontros.TestesUnidade`
  - `ProjetoEncontros.TestesIntegracao`

### Autenticacao

- Access token: 15 minutos
- Refresh token: 30 dias
- JWT para endpoints privados
- Refresh token revogavel

### Banco local

- PostgreSQL via Docker Compose
- Banco: `projeto_encontros`
- Usuario local: `projeto_encontros`
- Senha local apenas para desenvolvimento

### Persistencia

- Entity Framework Core: `10.0.4`
- Provider PostgreSQL: `Npgsql.EntityFrameworkCore.PostgreSQL` `10.0.2`
- Ferramenta local de migrations: `dotnet-ef` `10.0.4`
- Projeto do contexto: `ProjetoEncontros.Infraestrutura`
- Contexto: `ContextoDeBanco`
- Migration inicial: `Inicial`

### Tabelas iniciais

- `usuarios`
- `tokens_de_atualizacao`
- `grupos`
- `membros_do_grupo`
- `convites_do_grupo`
