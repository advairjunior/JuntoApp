# Projeto Encontros - v0.2.2 - Privacidade por Encontro

## Objetivo

Corrigir o modelo de privacidade dos encontros antes de evoluir para memorias.

A `v0.2.2` existe porque o produto nao deve assumir que todas as pessoas de uma turma, grupo ou circulo podem ver todos os encontros criados ali.

Na vida real, o mesmo conjunto de pessoas pode organizar encontros com participantes diferentes, limites diferentes e niveis diferentes de privacidade.

## Cenario real

Um grupo de amigos combina assistir a jogos do Brasil.

No primeiro jogo, 10 pessoas vao para uma casa.

No segundo jogo, apenas algumas pessoas conseguem ir.

No terceiro jogo, o encontro acontece em um apartamento com espaco limitado. Algumas pessoas ficam de fora e nao devem necessariamente saber que aquele encontro existiu.

Criar um novo grupo para cada variacao de convidados e ruim porque:

- duplica pessoas
- espalha memorias
- confunde historico
- cria muitos grupos quase iguais
- transforma o app em uma copia de grupos temporarios de WhatsApp

O problema correto nao e criar mais grupos.

O problema correto e permitir que cada encontro tenha sua propria lista privada de convidados.

## Decisao de produto

A privacidade principal deve estar no encontro.

Um usuario so deve visualizar um encontro quando:

- criou o encontro
- foi convidado para o encontro
- participa do encontro
- possui permissao explicita definida pela regra do encontro

Participar de uma turma, grupo ou circulo maior nao deve significar acesso automatico a todos os encontros.

## Mudanca conceitual

### Antes

```text
Grupo
  Membros
  Encontros visiveis para todos os membros
```

### Depois

```text
Turma ou Grupo
  Pessoas conhecidas
  Encontros
    Convidados do encontro
    Presencas do encontro
    Memorias do encontro
```

O grupo deixa de ser a fronteira final de privacidade.

O encontro passa a ser a fronteira principal de privacidade.

## Nome conceitual

O termo `Grupo` foi util para a fundacao inicial, mas pode estar carregando a ideia errada.

Termos candidatos:

- `Turma`
- `Circulo`
- `Grupo`

### Recomendacao inicial

Usar `Turma` na experiencia do usuario.

Motivos:

- soa humano e informal
- combina com amigos, familia, igreja, futebol e faculdade
- permite ter uma base de pessoas sem exigir que todos vejam tudo
- evita confusao com grupos de WhatsApp

No codigo, a migracao de nomes deve ser planejada com cuidado. A decisao de renomear entidades internas pode ficar para o plano tecnico.

## Regras de produto

### Turma ou grupo

Uma turma representa uma base de pessoas com convivencia ou relacao frequente.

Regras:

- uma turma possui pessoas
- uma turma pode sugerir convidados para encontros
- uma turma pode ter dono ou responsavel
- uma turma nao deve tornar todos os encontros visiveis automaticamente
- uma turma nao deve obrigar que todos participem de todos os encontros

### Encontro

Um encontro representa um momento real com pessoas especificas.

Regras:

- todo encontro deve possuir criador
- todo encontro pode estar associado a uma turma
- todo encontro deve possuir uma lista de convidados ou participantes
- apenas convidados ou participantes devem visualizar o encontro
- usuario externo ao encontro nao deve saber que o encontro existe
- o criador deve poder escolher quem sera convidado
- a lista de convidados pode ser menor que a lista de pessoas da turma

### Convite do encontro

Convite do encontro e diferente de convite para entrar na turma.

Regras:

- convite do encontro da acesso apenas ao encontro
- convite do encontro nao deve adicionar automaticamente a pessoa a toda a turma, salvo decisao futura explicita
- convite do encontro deve ter estado identificavel
- convite recusado nao deve permitir acesso ao encontro
- convite pendente pode permitir ou nao visualizacao limitada, conforme regra definida no plano tecnico

### Presenca

Presenca deve pertencer ao encontro, nao apenas ao grupo.

Regras:

- apenas convidado ou participante pode confirmar presenca
- a confirmacao de presenca nao deve expor o encontro para quem nao foi convidado
- a lista de presencas deve ser visivel apenas para pessoas autorizadas no encontro

### Memorias

Memorias futuras devem respeitar a privacidade do encontro.

Regras:

- memoria de encontro deve ser visivel apenas para pessoas autorizadas naquele encontro
- membro da turma que nao participou ou nao foi convidado nao deve acessar memorias do encontro
- fotos e videos devem seguir a mesma regra de visibilidade do encontro

## Funcionalidades da v0.2.2

### P0 - Convidados do encontro

Permitir que um encontro possua uma lista propria de convidados.

Valor:

Evita criar novos grupos para cada variacao de pessoas.

Regras:

- criador escolhe convidados ao criar ou editar o encontro
- convidados devem ser usuarios existentes ou convites pendentes, conforme decisao tecnica
- lista de convidados pode ser alterada enquanto o encontro permitir
- usuario nao convidado nao visualiza o encontro

### P0 - Listagem privada de encontros

Listar apenas encontros visiveis para o usuario atual.

Valor:

Preserva privacidade e evita constrangimento social.

Regras:

- usuario ve encontros que criou
- usuario ve encontros para os quais foi convidado
- usuario ve encontros em que participa
- usuario nao ve encontros da turma para os quais nao foi convidado

### P0 - Detalhe privado do encontro

Bloquear acesso ao detalhe de encontro para quem nao faz parte daquele encontro.

Valor:

Impede vazamento indireto de encontros privados.

Regras:

- usuario nao autorizado recebe acesso negado generico
- API nao deve informar se o encontro existe
- app nao deve exibir encontro invisivel em listas

### P1 - Convite rapido para encontro

Permitir convidar pessoas para um encontro de forma simples.

Valor:

Aproxima o app do fluxo real de combinados, sem virar chat.

Regras:

- convite pode ser por usuario ja conhecido na turma
- convite por e-mail ou link pode ser avaliado no plano tecnico
- convite por WhatsApp continua sendo canal futuro, nao regra obrigatoria

## Fora do escopo

- chat do encontro
- grupos temporarios descartaveis
- feed de encontros
- descoberta publica de encontros
- notificacao para quem nao foi convidado
- justificativa para quem ficou de fora
- ranqueamento de participantes
- mostrar encontros privados como "ocultos"
- permitir bisbilhotar agenda de uma turma inteira

## Impacto tecnico esperado

A implementacao deve ser planejada em documento tecnico proprio.

Pontos esperados:

- modelar convidados ou participantes do encontro
- separar membros da turma de convidados do encontro
- alterar consultas de listagem de encontros
- alterar autorizacao de detalhe, edicao, cancelamento e presenca
- revisar tela de criacao de encontro para escolher convidados
- revisar tela de detalhe da turma para nao expor encontros invisiveis
- preparar futuras memorias para usar privacidade do encontro

## Criterios de aceite

- Criador consegue criar encontro escolhendo convidados.
- Usuario convidado consegue visualizar o encontro.
- Usuario nao convidado nao visualiza o encontro.
- Usuario nao convidado nao acessa detalhe do encontro por rota direta.
- Usuario nao convidado nao confirma presenca.
- Listagem mostra apenas encontros visiveis para o usuario atual.
- Encontro privado nao revela sua existencia para quem nao foi convidado.
- Memorias futuras ficam vinculadas a regra de privacidade do encontro.

## Decisao final

O produto nao deve depender de criar um novo grupo sempre que a lista de pessoas mudar.

O grupo, turma ou circulo deve servir como base de convivencia.

O encontro deve decidir quem participa e quem pode ver.

Essa decisao protege a identidade do produto: organizar encontros reais entre as pessoas certas, com privacidade e simplicidade.
