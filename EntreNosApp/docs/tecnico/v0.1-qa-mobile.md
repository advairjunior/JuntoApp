# Projeto Encontros - QA Mobile v0.1

## Objetivo do documento

Este documento organiza a validacao manual prioritaria do aplicativo mobile da `v0.1 - Fundacao`.

Ele deve ser usado junto com:

- `../versoes/v0.1-fundacao.md`
- `spike-mobile-ios-maui.md`
- `v0.1-prontidao-ios.md`

## Escopo validado

A validacao mobile da v0.1 cobre:

- cadastro
- login
- sessao local
- listagem de grupos
- criacao de grupo pelo botao `+`
- detalhe do grupo
- envio de convite por e-mail
- aceite e recusa de convite
- listagem de membros
- remocao basica de membro comum pelo dono
- logout

Nao fazem parte desta validacao:

- encontros
- presenca em encontros
- memorias
- notificacoes push
- convites por WhatsApp
- funcionamento offline

## Checklist manual prioritario

### Conta e sessao

- [ ] Criar conta com nome, e-mail e senha validos.
- [ ] Bloquear cadastro com e-mail ja usado.
- [ ] Bloquear cadastro com dados obrigatorios ausentes.
- [ ] Fazer login com credenciais validas.
- [ ] Exibir erro compreensivel para login invalido.
- [ ] Fechar e reabrir o app mantendo a sessao quando houver token valido.
- [ ] Fazer logout e impedir acesso a areas privadas sem novo login.

### Grupos

- [ ] Usuario sem grupos deve ver estado vazio claro.
- [ ] Botao `+` deve abrir painel de criacao de grupo.
- [ ] Criar grupo com nome valido.
- [ ] Bloquear criacao de grupo sem nome.
- [ ] Grupo criado deve aparecer na lista.
- [ ] Tocar em um grupo deve abrir o detalhe correto.
- [ ] Recarregar deve atualizar grupos e convites.

### Convites

- [ ] Dono deve conseguir enviar convite por e-mail.
- [ ] Usuario convidado deve ver convite pendente na tela inicial.
- [ ] Usuario convidado deve conseguir aceitar convite.
- [ ] Ao aceitar, convite deve sair da lista e grupo deve aparecer.
- [ ] Usuario convidado deve conseguir recusar convite.
- [ ] Ao recusar, convite deve sair da lista e grupo nao deve aparecer.
- [ ] Convite duplicado deve gerar mensagem clara ou ser bloqueado.
- [ ] Convite para usuario ja membro deve ser bloqueado ou informado claramente.

### Membros

- [ ] Detalhe do grupo deve listar membros.
- [ ] Dono deve ver acao de remover membro comum.
- [ ] Membro comum nao deve ver acao administrativa de remover.
- [ ] Dono nao deve conseguir remover a si mesmo pelo app.
- [ ] Remover membro comum deve atualizar a lista.
- [ ] Membro removido nao deve conseguir acessar o grupo apos recarregar.

### Resiliencia e UX

- [ ] Perda de conexao deve exibir mensagem clara.
- [ ] Acoes em andamento nao devem gerar duplicidade com toque repetido.
- [ ] Campos nao devem ficar escondidos pelo teclado em fluxo principal.
- [ ] Mensagens de erro nao devem expor stack trace, token ou detalhes internos.
- [ ] Fluxos principais devem ser utilizaveis com uma mao.

## Riscos prioritarios

- Convite duplicado por toque repetido ou reenvio para o mesmo e-mail.
- Lista desatualizada apos criar grupo, aceitar convite ou remover membro.
- Usuario removido continuar vendo grupo por sessao antiga.
- Regra de permissao existir apenas no app e nao na API.
- E-mail com letras maiusculas/minusculas gerar duplicidade indesejada.
- Loading infinito em falha de rede.
- Remocao deixar grupo sem responsavel.

## Criterio minimo para fechar QA v0.1 mobile

A v0.1 mobile pode ser considerada pronta para validacao em dispositivo quando:

- cadastro e login funcionarem sem Swagger
- criacao e abertura de grupo funcionarem pelo app
- convite por e-mail funcionar entre dois usuarios reais
- aceite e recusa atualizarem a tela inicial corretamente
- dono conseguir remover membro comum
- membro removido perder acesso ao grupo
- erros principais forem compreensiveis para usuario comum
- nenhum fluxo principal depender de acao manual no banco ou Swagger
