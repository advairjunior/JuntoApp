## Casos de teste

### QA-04-001 - Listar combinados de um encontro

Objetivo:

- garantir que um participante veja os combinados do encontro.

Pre-condicoes:

- usuario autenticado.
- usuario participante do encontro.
- encontro com pelo menos um combinado.

Passos:

1. Abrir o encontro.
2. Abrir a area de combinados.
3. Observar a lista.

Resultado esperado:

- a lista deve exibir apenas itens do encontro aberto.
- cada item deve mostrar descricao, situacao e responsavel quando existir.

Prioridade: P0

Tipo: funcional

### QA-04-002 - Criar combinado sem responsavel

Objetivo:

- garantir que o usuario crie um item simples rapidamente.

Pre-condicoes:

- usuario autenticado.
- usuario participante do encontro.

Passos:

1. Abrir a tela `Combinados`.
2. Acionar criacao.
3. Informar uma descricao valida.
4. Nao escolher responsavel.
5. Salvar.

Resultado esperado:

- o item deve ser criado como `Pendente`.
- o item deve aparecer na lista.
- o feed deve registrar uma atualizacao automatica.

Prioridade: P0

Tipo: funcional

### QA-04-003 - Criar combinado com responsavel

Objetivo:

- garantir que um item possa nascer com responsavel opcional.

Pre-condicoes:

- usuario autenticado.
- usuario participante do encontro.
- encontro com mais de um participante.

Passos:

1. Abrir a tela `Combinados`.
2. Acionar criacao.
3. Informar uma descricao valida.
4. Selecionar um participante como responsavel.
5. Salvar.

Resultado esperado:

- o item deve exibir o responsavel escolhido.
- o feed deve registrar a criacao.
- o feed deve registrar quem ficou responsavel, quando aplicavel.

Prioridade: P1

Tipo: funcional

### QA-04-004 - Rejeitar responsavel externo

Objetivo:

- garantir que um item nao seja atribuido a usuario fora do encontro.

Pre-condicoes:

- usuario autenticado.
- usuario participante do encontro.
- identificador de usuario que nao participa do encontro.

Passos:

1. Enviar requisicao para criar ou atribuir item com usuario externo.

Resultado esperado:

- a operacao deve ser rejeitada.
- o item nao deve ficar associado ao usuario externo.

Prioridade: P0

Tipo: seguranca

### QA-04-005 - Resolver combinado

Objetivo:

- garantir que participantes consigam indicar que um combinado foi resolvido.

Pre-condicoes:

- usuario autenticado.
- usuario participante do encontro.
- item pendente existente.

Passos:

1. Abrir a tela `Combinados`.
2. Acionar `Resolver` no item pendente.

Resultado esperado:

- o item deve mudar para `Resolvido`.
- a lista deve continuar exibindo o item.
- o feed deve registrar uma atualizacao automatica.

Prioridade: P1

Tipo: funcional

### QA-04-006 - Editar combinado

Objetivo:

- garantir que um combinado existente possa ser corrigido sem recriar o item.

Pre-condicoes:

- usuario autenticado.
- usuario participante do encontro.
- item existente.

Passos:

1. Abrir a tela `Combinados`.
2. Tocar em um item existente.
3. Alterar a descricao.
4. Alterar, remover ou escolher responsavel.
5. Salvar.

Resultado esperado:

Prioridade: P1

Tipo: funcional

### QA-04-009 - Bloquear usuario externo

Objetivo:

- garantir privacidade dos combinados do encontro.

Pre-condicoes:

- usuario autenticado.
- usuario nao participante do encontro.

Passos:

1. Tentar listar itens do encontro.
2. Tentar criar item no encontro.
3. Tentar editar item do encontro.
4. Tentar alterar situacao de item do encontro.
5. Tentar excluir item do encontro.

Resultado esperado:

- todas as operacoes devem ser bloqueadas.
- nenhum dado privado do encontro deve ser exposto.

Prioridade: P0

Tipo: seguranca

### QA-04-010 - Atualizacao automatica no feed

Objetivo:

- garantir que combinados importantes aparecam no contexto vivo do encontro.

Pre-condicoes:

- usuario autenticado.
- usuario participante do encontro.
- feed do encontro aberto ou acessivel.

Passos:

1. Criar um combinado.
2. Editar o combinado.
3. Atribuir responsavel.
4. Marcar como resolvido.
5. Reabrir o item.
6. Excluir o item.
7. Abrir o feed do encontro.

Resultado esperado:

- o feed deve exibir atualizacoes do sistema para cada acao relevante.
- essas atualizacoes devem ser discretas e diferentes das mensagens dos participantes.

Prioridade: P1

Tipo: integracao

## Observacoes de QA

### Edicao e exclusao de combinados

Estado:

- implementado como refinamento final da v0.4.

Analise:

- editar e apagar itens completa o ciclo basico de manutencao dos combinados.
- a experiencia foi mantida simples para nao transformar a tela em um gerenciador profissional de tarefas.

Recomendacao:

- manter edicao e exclusao apenas no nivel simples atual.
- nao adicionar historico detalhado, prioridade, prazo ou anexos nesta versao.

### Validacao em iPhone real

Estado:

- pendente futuro.

Analise:

- o app tem direcao iOS, mas a validacao local foi feita no ambiente disponivel.

Recomendacao:

- antes de qualquer distribuicao externa, validar toque, teclado, largura, scroll e area segura em iPhone real ou simulator iOS configurado.

## Resultado final

A versao `0.4 - Organizacao Colaborativa` esta funcionalmente pronta para validacao manual final no aplicativo.

O fluxo principal de combinados agora cobre criar, listar, editar, trocar responsavel, remover responsavel, resolver, reabrir e excluir.
