# Projeto Encontros - Visao do Produto

## Objetivo do documento

Este documento define a visao do produto, sua missao, seu publico, seus limites e os principios que devem orientar todas as decisoes futuras.

Ele deve ser usado como referencia antes de criar funcionalidades, definir prioridades, desenhar telas, planejar versoes ou tomar decisoes tecnicas.

## Nome do projeto

O nome definitivo do aplicativo ainda nao foi escolhido.

Durante a fase de documentacao e planejamento, o produto sera chamado de **Projeto Encontros**.

Quando o nome oficial for definido, a documentacao devera ser revisada para substituir o nome provisorio de forma consistente.

## Visao geral

O Projeto Encontros e um aplicativo mobile privado criado para grupos de pessoas que possuem convivencia frequente.

Seu objetivo e facilitar a organizacao dos encontros e preservar as memorias criadas pelo grupo ao longo dos anos.

O produto existe para ajudar pessoas que ja convivem ou desejam conviver mais a organizar momentos reais, registrar lembrancas e manter vivo o historico afetivo do grupo.

A tecnologia deve servir como apoio para a convivencia, nao como substituta dela.

## Missao

Criar o melhor aplicativo para organizar encontros entre pessoas e guardar suas melhores lembrancas.

O Projeto Encontros deve incentivar as pessoas a viverem momentos juntas no mundo real. A tecnologia existe apenas para facilitar, organizar e preservar esses momentos.

## Identidade do produto

O Projeto Encontros deve ser lembrado como:

> O aplicativo onde nosso grupo organiza encontros e guarda nossas melhores lembrancas.

Toda decisao de produto, arquitetura, experiencia, conteudo ou interface deve preservar essa identidade.

Se uma funcionalidade aproximar o produto de uma rede social comum, de um aplicativo de mensagens ou de uma plataforma voltada a consumo excessivo de tela, ela devera ser questionada antes de ser aceita.

## Publico-alvo

O Projeto Encontros podera ser utilizado por qualquer grupo de pessoas que goste de estar junto e precise organizar momentos compartilhados.

Exemplos de grupos:

- amigos
- familia
- igreja
- ministerio de musica
- banda
- faculdade
- trabalho
- futebol
- churrasco
- viagens
- estudos
- qualquer grupo com convivencia frequente

O produto deve ser simples o bastante para grupos informais e organizado o bastante para grupos com rotinas recorrentes.

## Problema que o produto resolve

Grupos costumam organizar encontros, listas, combinados, fotos e lembrancas em ferramentas espalhadas.

Com o tempo, informacoes importantes se perdem em conversas, arquivos ficam desorganizados, fotos deixam de estar associadas ao momento em que aconteceram e o historico do grupo se fragmenta.

O Projeto Encontros resolve esse problema ao oferecer um espaco privado e organizado para:

- planejar encontros
- registrar presencas
- organizar combinados
- guardar fotos, videos e lembrancas
- preservar a historia do grupo ao longo dos anos

## O que o produto e

O Projeto Encontros e:

- um aplicativo privado para grupos
- uma ferramenta de organizacao de encontros
- um espaco para preservar memorias
- um historico afetivo do grupo
- um apoio para convivencia no mundo real
- um produto simples, direto e focado em valor real para o usuario

## O que o produto nao e

O Projeto Encontros nao e:

- uma rede social
- um aplicativo de mensagens
- um substituto para WhatsApp, Discord, Telegram ou Instagram
- uma plataforma para publicacoes abertas
- uma ferramenta para estimular consumo infinito de conteudo
- um produto construido para competir por tempo de tela

O produto pode complementar ferramentas de comunicacao, mas nao deve tentar substitui-las.

## Pilares do produto

Toda funcionalidade devera fortalecer pelo menos um dos pilares abaixo.

### Organizacao

O produto deve ajudar o grupo a organizar encontros, combinados, listas, responsabilidades e informacoes importantes.

Uma funcionalidade fortalece este pilar quando reduz confusao, evita esquecimentos ou facilita a preparacao de um encontro.

### Encontros

O produto deve incentivar momentos presenciais e facilitar a participacao das pessoas.

Uma funcionalidade fortalece este pilar quando torna mais facil marcar, confirmar, acompanhar ou realizar encontros no mundo real.

### Memorias

O produto deve preservar os momentos vividos pelo grupo.

Uma funcionalidade fortalece este pilar quando ajuda a registrar, encontrar ou reviver fotos, videos, lembrancas, acontecimentos e historicos.

### Amizade

O produto deve fortalecer vinculos entre pessoas.

Uma funcionalidade fortalece este pilar quando aproxima o grupo, valoriza experiencias compartilhadas ou reforca a sensacao de pertencimento.

### Simplicidade

O produto deve ser facil de entender e rapido de usar.

Uma funcionalidade fortalece este pilar quando reduz passos, evita complexidade desnecessaria ou torna uma acao mais clara.

### Experiencia do usuario

O produto deve ser agradavel, direto e confortavel para pessoas comuns.

Uma funcionalidade fortalece este pilar quando melhora clareza, navegacao, acessibilidade, feedback visual ou facilidade de uso.

## Principios de decisao

Sempre que houver duvida sobre uma funcionalidade, decisao tecnica ou experiencia de uso, os seguintes principios devem orientar a escolha:

1. O produto deve incentivar pessoas a se encontrarem no mundo real.
2. O produto deve fortalecer amizades e vinculos reais.
3. O produto deve registrar memorias importantes para o grupo.
4. O produto deve ser extremamente simples.
5. O produto nao deve competir com redes sociais.
6. O produto nao deve estimular uso excessivo da tela.
7. Quanto menos toques forem necessarios para concluir uma acao, melhor.
8. Toda funcionalidade precisa justificar seu valor para o produto.
9. Organizacao e memoria sao mais importantes do que volume de interacao.
10. A identidade do produto deve ser preservada mesmo quando surgirem ideias novas.

## Criterios para aceitar uma funcionalidade

Uma funcionalidade so deve ser aceita quando responder positivamente as perguntas abaixo:

- Ela fortalece pelo menos um pilar do produto?
- Ela ajuda pessoas a organizarem encontros ou preservarem memorias?
- Ela simplifica a vida do grupo?
- Ela respeita a identidade do Projeto Encontros?
- Ela evita transformar o produto em rede social ou aplicativo de mensagens?
- Ela pode ser explicada de forma simples para um usuario comum?
- Ela entrega valor claro em uma versao planejada do produto?

Se a resposta for negativa ou incerta, a funcionalidade deve ser questionada, simplificada, adiada ou rejeitada.

## Tom de experiencia

O Projeto Encontros deve transmitir:

- amizade
- organizacao
- simplicidade
- diversao
- nostalgia
- privacidade
- cuidado com as memorias do grupo

A experiencia deve parecer humana e acolhedora, mas sem perder clareza e objetividade.

O produto deve evitar excesso de elementos visuais, fluxos longos, competicao por atencao e qualquer mecanismo que incentive uso compulsivo.
